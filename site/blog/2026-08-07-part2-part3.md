LEX 장에는 실행 가능한 flex 예제 넷을 붙였다.

## 오토마타를 컴포넌트로 만든 이유

부분집합 구성은 글로 읽으면 지루하고, 한 단계씩 눌러 보면 5분이면 이해된다.
그래서 세 개를 만들었다.

- `AutomatonDiagram` — 상태·간선 스펙에서 SVG 전이도. 자기 고리, 양방향 간선
  자동 곡률 배분, 활성 상태 강조.
- `AutomatonSimulator` — **NFA와 DFA를 코드 하나로 처리**한다.
  내부적으로 항상 상태 *집합*을 들고 다니며 매 단계 ε-closure 를 취한다.
  DFA 는 그 집합의 크기가 늘 1인 특수한 경우일 뿐이다.
- `SubsetConstruction` — 워크리스트에서 하나씩 꺼내 표를 채운다.
  결과가 Dragon Book 의 A~E 명명과 정확히 일치하는지 확인했다.

## 빌드가 통과하는데 화면이 틀린 경우

이번에 두 번 겪었다. 둘 다 **빌드는 성공하고 경고도 없는데 결과가 틀린** 종류다.

### 1. KaTeX 안의 `$`

```
$\text{$\varepsilon$-closure}(T)$
```

KaTeX 문법으로는 맞다. 그런데 remark-math 가 안쪽 `$` 를 닫는 구분자로 읽어서
수식이 거기서 끊긴다. 결과적으로 뒤쪽 `$` 들의 짝이 전부 밀리고,
그 여파로 **바로 아래 admonition 까지 깨졌다**.

`\varepsilon\text{-closure}` 로 쓰면 된다.

### 2. `:::tip 제목` 이 조용히 버려진다

이게 더 고약했다. Docusaurus 3(MDX v3)은 admonition 제목을
`:::tip[제목]` 대괄호 문법으로 받는다. 예전의 공백 문법은
**경고 하나 없이 그냥 일반 문단**이 되어 `:::` 가 본문에 그대로 찍힌다.

빌드 로그만 보고 있었으면 끝까지 몰랐을 것이다.
브라우저로 실제 페이지를 열어 보고 나서야 발견했다.
확인 방법은 단순했다.

```bash
grep -c 'theme-admonition' build/docs/*/index.html   # 전부 0 이었다
```

문서 전체의 admonition 58개를 일괄 변환했다.
**교훈: 정적 사이트도 렌더링 결과를 직접 봐야 한다.**

## 예제는 전부 실제로 돌아간다

`examples/` 아래 네 디렉터리, 모두 `make test` 로 검증한다.

| 예제 | 보여 주는 것 |
|---|---|
| `01-lex-wordcount` | lex 파일의 3부 구조, `yytext`/`yyleng` |
| `02-lex-tokenizer` | 최장 일치, 규칙 순서, catch-all 의 필요성 |
| `03-dfa-by-hand` | 전이표 구동 vs 직접 코딩, 두 구현의 일치 검증 |
| `04-lex-states` | 시작 조건, 중첩 주석, 이스케이프 해석, `<<EOF>>` |

문서에 실은 도구 출력은 전부 실제로 실행해 붙여 넣은 것이다.
`flex -v` 의 상태 수, `flex -d` 의 매치 추적, `flex -b` 의 되감기 보고서,
규칙 순서를 뒤집었을 때 나오는 `rule cannot be matched` 경고까지 확인했다.

`02-lex-tokenizer` 의 `flex -v` 결과가 특히 설득력 있었다.

```
  273/2000 NFA states
  92/1000 DFA states (493 words)
```

토큰 종류가 30가지 남짓인데 NFA 가 273상태다.
"이걸 손으로 관리할 수 없다"가 lex 의 존재 이유라는 말을,
숫자로 보여 줄 수 있게 됐다.
