## 기술 선택

- **Docusaurus 3 + TypeScript + bun.** 문서 사이트에 필요한 것
  (검색, 사이드바, 다크 모드, MDX, 버전 관리)이 전부 기본으로 들어 있고,
  교안처럼 "순서가 있는 긴 문서"에 사이드바 모델이 잘 맞는다.
- **Mermaid** — 오토마타 상태 전이도, 파스 트리, 파이프라인 다이어그램을
  이미지가 아니라 **텍스트로** 관리하려고 도입했다.
  다이어그램이 문서와 함께 diff에 남고, 다크 모드에서 자동으로 색이 바뀐다.
- **KaTeX** — $\Sigma^*$, $\delta(q, a)$, $A \Rightarrow^* w$ 같은 표기가
  교안 전체에 계속 나온다. 이미지로 넣으면 검색도 복사도 안 된다.

## `markdown.format: 'detect'` 로 바꾼 이유

Docusaurus 3는 기본적으로 `.md` 파일도 MDX로 파싱한다.
그런데 이 교안 본문에는 `{a, b}`(집합), `<expr>`(BNF) 같은 표기가 끝없이 나온다.
MDX는 `{`를 JS 표현식으로, `<`를 JSX 태그로 해석하므로 그대로 두면 빌드가 깨진다.

```ts
markdown: {
  mermaid: true,
  format: 'detect',   // .md → CommonMark, .mdx → MDX
},
```

`detect`로 두면 `.md`는 순수 CommonMark로 처리된다.
admonition, Mermaid, KaTeX는 전부 remark 플러그인이라 그대로 동작하고,
React 컴포넌트가 필요한 페이지만 `.mdx`로 쓰면 된다.
오토마타 시뮬레이터 같은 인터랙티브 요소는 그쪽에 넣을 계획이다.

## 집필 중 `onBrokenLinks: 'warn'`

교안은 앞 장에서 뒷 장을 계속 참조한다.
1장에서 "이건 [2부 정규언어]에서 증명한다"라고 쓰려면 그 페이지가 이미 있어야 하는데,
순서대로 쓰다 보면 당연히 없다.

집필 기간에는 `'warn'`으로 두고 최종 검증 단계에서 `'throw'`로 되돌리기로 했다.
그래야 링크를 나중에 다시 붙이는 수고 없이 처음부터 최종 URL로 쓸 수 있다.

## 리서치 먼저

교안 본문을 쓰기 전에 최신 동향부터 조사했다.
6부에 몰아넣을 내용이지만, 앞 장들에서도
"이 이론이 지금 어디에 쓰이는지"를 짚어 주고 싶었기 때문이다.

조사 결과는 저장소의 `research/RESEARCH-NOTES.md`에 출처와 함께 정리해 두었다.
주요 갈래는 다섯이다.

1. **점진적 파싱** — tree-sitter의 GLR 기반 재파싱, gpeg의 로그 시간 재파싱
2. **PEG** — DuckDB가 SQL 파서를 런타임 확장 가능하게 만든 사례, labeled failure 오류 복구
3. **MLIR** — 다층 dialect IR, CGO 2025의 Transform Dialect 논문
4. **검증된 컴파일러** — CompCert와 그 위에 쌓인 최근 검증 사례
5. **LLM** — CC 2025의 LLM Compiler 등, 최적화 휴리스틱 탐색 쪽에 성과가 몰려 있다는 점

다섯 번째와 관련해 교안에 반영할 관점을 하나 정했다.
**어휘·구문 분석처럼 결정론적 정확성이 필요한 프론트엔드는 여전히 형식 문법 + 생성기의
영역이고, LLM이 실제로 성과를 낸 곳은 최적화 휴리스틱 탐색과 auto-tuning 쪽**이라는 것.
두 영역을 섞어서 이야기하지 않으려고 한다.
