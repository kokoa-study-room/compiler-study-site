## 감사 방법

느낌으로 판단하지 않고 기계적으로 훑었다.

```bash
# 표준 교재 주제 중 언급조차 없는 것
for t in "속성 문법" "구문 지향 번역" "합성 속성" "연산자 우선순위 파싱" "입력 버퍼링"; do
  grep -rc "$t" --include='*.md' --include='*.mdx' .
done

# 용어의 첫 등장 위치 vs 용어 사전이 가리키는 장
# 확인 문제 개수 vs <details> 해설 개수
```

## 1. 가장 큰 구멍 — 속성 문법이 통째로 없었다

```
속성 문법 (attribute grammar)   ✗ 전혀 없음
구문 지향 번역 (SDD/SDT)        ✗ 전혀 없음
합성 속성 / 상속 속성            ✗ 전혀 없음
S-속성 / L-속성 문법             ✗ 전혀 없음
```

`$$ = $1 + $3` 을 **실무적으로**는 가르쳤는데,
그것이 **합성 속성**이라는 것, yacc가 **S-속성 문법만 자연히 지원**한다는 것,
그래서 상속 속성이 필요하면 **중간 액션**을 써야 한다는 인과가 빠져 있었다.

"중간 액션은 위험하다"고만 하고 **왜 그런 상황이 생기는지**를 말하지 않은 셈이다.

17장을 새로 썼다. 핵심 결론은 한 줄이다.

> **LR(yacc)은 값을 위로 올리기(합성 속성)에 강하고,
> LL(재귀 하강)은 값을 아래로 내리기(상속 속성)에 강하다.**

13장에서 `parse_E_prime(Node *left)` 의 `left` 인자가 사실 **상속 속성**이었다는
것도 이제 연결된다.

## 2. 가장 어려운 두 계산의 과정이 생략되어 있었다

**LR(0) 항목 집합.** 15.3절이 CLOSURE/GOTO 정의만 주고
완성된 11개 집합을 바로 제시하고 있었다. 학생이 재현할 수 없다.

$I_0$ 를 회차별로 전개하고, `GOTO(I₀, E)` / `GOTO(I₀, '(')` 를 각각 계산하는
과정을 넣었다. 그리고 이것이 6장 **부분집합 구성과 완전히 같은 알고리즘**임을
대조표로 연결했다.

| | 부분집합 구성 | 정준 집합 구성 |
|---|---|---|
| 상태 = | NFA 상태의 집합 | LR(0) 항목의 집합 |
| 한 걸음 | `ε-closure(move(T,a))` | `CLOSURE(점 옮기기)` |

**followpos.** 6.7절도 규칙표만 주고 답 표로 점프하고 있었다.
구문 트리 그림과 노드별 `nullable`/`firstpos`/`lastpos` 계산표를 추가했다.

## 3. 정의 없이 쓰이던 용어들

| 용어 | 문제 |
|---|---|
| **심볼 테이블** | 1장 다이어그램에 등장, 정의는 **19장** |
| **lookahead** | 30회 이상 쓰는데 괄호 한 마디가 전부 |
| **렉심(lexeme)** | 용어 사전이 7장을 가리키는데 **7장에 그 단어가 없었다** |
| **$2^Q$ (멱집합)** | 5장 NFA 정의에 설명 없이 등장 |
| **비둘기집 원리** | 증명 두 곳의 근거인데 정의 없음 |

전부 첫 등장 자리에서 정의하도록 고쳤다.
그리고 **선수 지식 안내가 아예 없었다** — `grep "선수\|알고 있어야"` 가 0건이었다.
"시작하기 전에" 페이지를 새로 만들어 필요한 C 문법(포인터·구조체·`union`·가변인자),
집합/함수 표기, 귀류법·비둘기집 원리, 트리 순회를 정리했다.

## 4. 확인 문제 120개에 정답이 하나도 없었다

독학용으로는 반쪽이다. 전부 접이식 `<details>` 로 달았다.

```md
<details>
<summary>풀이</summary>

**(b) 증명.** $w = 0^p1^p$ 를 택한다. …

</details>
```

먼저 풀어 본 뒤 펼쳐 보는 방식이라 학습 효과를 해치지 않는다.

## 덤으로 잡은 내용 오류

**4장의 역참조 예시가 틀렸다.**

> 역참조 `(a+)\1` 은 $\{ww \mid w \in a^+\}$ 를 나타내는데,
> 이는 펌핑 보조정리로 정규가 아님을 보일 수 있다.

**틀렸다.** 알파벳이 `a` 하나뿐이면
$\{ww \mid w \in a^+\} = \{a^{2n}\}$ 이고, 이것은 `(aa)+` 로 쓸 수 있는
**정규언어**다.

`([ab]+)\1` 로 고치고, **알파벳 크기가 왜 결정적인지**를 설명하는 블록을 넣었다.
역참조가 표현력을 늘리려면 "같은 것"이 여러 가지일 수 있어야 —
즉 기호가 둘 이상이어야 — 기억할 정보가 무한해진다.

## 표기 문제 두 가지

**수식 안의 `\|`.** 37곳에서 `$\|xy\| \leq p$` 라고 썼는데,
KaTeX에서 `\|` 는 **이중선 ‖** 다. 절댓값이 ‖xy‖ 로 나오고 있었다.

Markdown 표 안에서는 맨 `|` 가 열 구분자라 escape가 필요하고,
그러면 KaTeX가 이중선으로 읽는다. 파이프를 아예 쓰지 않는
`\lvert` / `\rvert` 로 통일해 두 문제를 함께 해결했다.

**헤딩 안의 수식.** 목차에는 KaTeX가 적용되지 않아
`### 증명 예제 — $\{a^n b^n\}$ 은 …` 이 TOC에 `\(a^n b^n\)` 로 노출되고 있었다.
수식을 빼고 `{#proof-anbn}` 으로 **명시적 id**를 달았다.

한국어 헤딩은 슬러그 예측이 어렵다.
`### 모호성 제거 ② — dangling else` 의 슬러그는 `모호성-제거---dangling-else` —
하이픈이 **셋**이다. `②` 와 `—` 가 제거되며 공백 셋이 남기 때문인데,
세어 보지 않으면 맞히기 어렵다. 자주 참조하는 헤딩에는 명시적 id를 권한다.
