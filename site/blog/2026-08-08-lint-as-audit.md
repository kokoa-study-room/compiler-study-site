그래서 이번에는 결함을 고치는 데서 멈추지 않고, **감사 자체를 스크립트로 만들었다.**

## 왜 같은 버그가 또 나왔나

지난 감사에서 이런 것들을 고쳤다.

- `:::tip 제목` 이 조용히 버려진다 → 58곳을 대괄호로
- 수식 안의 `\|` 가 ‖ 로 렌더링된다 → 37곳을 `\lvert` `\rvert` 로
- 인라인 수식 안의 `$` 에서 수식이 끊긴다 → 발견한 곳을 코드 스팬으로

전부 **찾아서 고쳤다.** 그런데 이번에 다시 세어 보니

```
인라인 수식 안의 \$   9곳
수식 안의 \|          3곳
```

지난번에 못 찾은 것이 남아 있었고, 그 뒤에 쓴 글에서 새로 생기기도 했다.

당연한 결과다. **사람이 눈으로 찾는 검사는 반복되지 않는다.**
`onBrokenLinks: 'throw'` 는 매 빌드마다 돌지만, "수식이 제대로 보이는지"는 아무도 안 본다.

## 특히 위험한 종류

`.mdx` 에서 수식이 끊기면 뒤따르는 `{...}` 가 JSX로 해석되어 **빌드가 실패한다.**
이건 괜찮다. 바로 안다.

문제는 `.md` 다. **경고 없이 잘못 렌더링된다.**

```md
$\mathrm{FOLLOW}(S) = \{\$\}$ 도 상속받는다.
```

빌드된 HTML을 뜯어 보니 이렇게 나오고 있었다.

```
그리고 B 가 nullable 이므로 \mathrm{FOLLOW}(S) = \{\}$ 도 상속받는다.
```

**원본 LaTeX이 그대로 노출**되고, `$` 는 사라졌다.
링크 검사도, 타입 검사도, 44개 유닛 테스트도 이걸 못 잡는다.

## lint-docs.ts

그래서 규칙 일곱 개를 스크립트로 옮겼다.
전부 **빌드는 통과하는데 결과가 틀리는** 것들이다.

| 규칙 | 증상 |
|---|---|
| 인라인 수식 안의 `\$` | 수식이 끊기고 LaTeX이 노출된다 |
| 수식 안의 `\|` | KaTeX가 ‖(이중선)로 그린다 |
| 공백 제목 admonition | Docusaurus 3가 경고 없이 버린다 |
| 이중 백틱 코드 스팬 | 백틱이 본문에 그대로 찍힌다 |
| 링크 표시 장 번호 | 재번호 후 앵커만 고치면 남는다 |
| 헤딩 안의 수식 | 목차에 원본 LaTeX이 노출된다 |
| 확인 문제 수 ≠ 해설 수 | 풀이가 빠진 장 |

`bun run check` 에 물려서 빌드 전에 돈다.

```bash
$ bun run lint
✓ lint-docs: 문제 없음
```

### 다섯 번째 규칙이 잡은 것

장 번호 검사는 이번에 새로 추가했는데, 바로 **31곳**이 나왔다.

```
reference/glossary.md:122  [17](/docs/yacc/yacc-grammar-and-actions#194-심볼-테이블)  → 실제 19장
reference/cheatsheet.md:364  [16](/docs/yacc/yacc-overview)  → 실제 18장
labs/yacc-labs.md:198  [16. YACC 개요](/docs/yacc/yacc-overview)  → 실제 18장
```

지난번에 장 두 개를 새로 끼워 넣으며 7개 장을 재번호했다.
그때 **앵커는 전부 고쳤다.** 그래서 `onBrokenAnchors: 'throw'` 가 통과했다.
고치지 않은 것은 **링크에 보이는 숫자**였다.

용어 사전의 "심볼 테이블 → 17장" 링크를 누르면 19장으로 간다.
링크는 멀쩡히 작동한다. 숫자만 거짓말을 한다.

경로에서 장 번호를 역산할 수 있으니, 그 대응표 하나로 전부 잡힌다.

## 내용 쪽에서 나온 가장 큰 것

### LR(1)을 정의만 하고 계산하지 않았다

지난 감사에서 "LR(0) 항목 집합이 정의만 있고 계산이 없다"를 고쳤다.
그런데 **바로 그 다음 절인 LR(1)·LALR(1)은 그대로 두었다.**

```
CLOSURE 도 바뀐다. [A → α·Bβ, a] 로부터 B → γ 에 대해
[B → ·γ, b]  for each b ∈ FIRST(βa) 를 추가한다.

위 예에서 R → L· 의 lookahead 는 $ 뿐이므로 = 와 충돌하지 않는다.
```

규칙을 적고, 한 번도 돌리지 않고, **결론을 단정했다.**
"lookahead 가 `$` 뿐"이라는 것을 학생이 확인할 방법이 없다.

$I_0$ 부터 회차별로 전개하고, $I_0 \sim I_{13}$ 을 다 만들고,
LALR 병합으로 14개가 10개가 되는 과정을 표로 넣었다.

핵심은 $I_2$ 다.

$$
I_2 = \{\,[S \to L\cdot = R,\ \$],\ \ [R \to L\cdot,\ \$]\,\}
$$

$R \to L\cdot$ 의 lookahead 가 `$` 하나뿐이라 `=` 열이 비고, 충돌이 없다.
그리고 $I_2$ 는 **코어가 유일해서 병합 상대가 없다** — LALR에서도 그대로 살아남는다.

bison으로 확인했다.

```
state 4

    1 S: L . '=' R
    5 R: L .

    '='  shift, and go to state 9
    $default  reduce using rule 5 (R)
```

`=` 는 shift로만 적혀 있다. 손계산과 같다.

### 용어 사전이 두 장을 통째로 빠뜨렸다

새로 쓴 14장(연산자 우선순위)과 17장(구문 지향 번역)의 용어가 **하나도 없었다.**
합성 속성, 상속 속성, S-속성, L-속성, 의존 그래프 — 전부.

더 놀란 것은 **LL(1), SLR(1), LALR(1), LR(1) 자체가 없었다**는 점이다.
`LR(0) 항목`은 있는데 정작 파서 부류 이름이 없었다.

89 → 150항목으로 늘렸다.

## 새로 넣은 것

**부트스트랩과 T-다이어그램**(1.5). "C 컴파일러는 무엇으로 컴파일했나"라는
당연한 의문에 답하는 자리가 없었다. stage2/stage3 바이트 동일성 검사와
Thompson의 "Reflections on Trusting Trust"까지 이었다.

**CFG → PDA 구성**(10.3). "좌측 유도를 스택으로 흉내 낸다"고만 쓰고
실제 변환을 보이지 않고 있었다. 세 규칙을 적고 괄호 문법으로 돌렸다.
전개 규칙을 고를 때 생기는 비결정성이 곧 LL/LR의 갈림길이라는 것까지 연결했다.

**재진입 스캐너와 유니코드**(9.10 + 예제 09). 유니코드 쪽이 재미있다.

```lex
[가-힣]+  { printf("HANGUL[%s]\n", yytext); }
```

한글만 넣으면 잘 되는 것처럼 보인다. 다른 걸 넣으면

```
$ printf 'こんにちは café 中文\n' | ./u
HANGUL[こんにちは]
ASCII[caf]
HANGUL[é]
HANGUL[中文]
```

일본어도 중국어도 `é` 도 "한글"이 됐고, `café` 는 둘로 쪼개졌다.

`가` = `EA B0 80`, `힣` = `ED 9E A3` 이므로 flex는 이 클래스를
바이트 나열 `[EA, B0, 80-ED, 9E, A3]` 으로 읽는다.
가운데 `80-ED` 가 모든 UTF-8 다중바이트를 삼킨다.

**한국어로만 테스트하면 통과하는 버그다.**

## 남는 생각

이번 감사에서 고친 것 중 **절반 이상이 지난 감사에서 이미 알고 있던 종류**였다.
아는 것과 안 나는 것은 다르다.

`onBrokenLinks: 'throw'` 를 켜 둔 덕분에 링크는 한 번도 깨진 적이 없다.
같은 일을 렌더링 결과에도 해 준 셈이다.

```bash
cd site && bun run check      # lint + typecheck + 44 tests + build
cd examples && make test      # 9개 예제 27케이스
```
