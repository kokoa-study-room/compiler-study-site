접이식 풀이 125개를 달아 두고 정작 **인쇄를 해 본 적이 없었다.**

<!-- truncate -->

## 종이에는 문제만 나온다

확인 문제 풀이는 전부 이렇게 되어 있다.

```md
<details>
<summary>풀이</summary>

**귀류법.** $L$ 이 정규라 가정하고 …

</details>
```

화면에서는 눌러서 펼치면 된다. 그런데 **닫힌 `<details>` 는 `<summary>` 만 인쇄된다.**
시험 준비로 출력하면 문제 125개가 나오고 풀이는 한 줄도 안 나온다.

CSS로 해결하려면 이렇게 쓴다.

```css
@media print {
  details > *:not(summary) { display: revert !important; }
}
```

그런데 닫힌 `<details>` 의 내용을 감추는 방식이 브라우저마다 다르다.
확실한 쪽은 인쇄 직전에 `open` 을 켜는 것이다.

```ts
window.addEventListener('beforeprint', openAll);
window.addEventListener('afterprint', restore);
```

**원래 열려 있던 것은 기억해 두었다가 그대로 둔다** — 인쇄했다고 화면 상태가
바뀌면 안 되기 때문이다.

확인해 봤다.

```
{"전체":6, "인쇄전":0, "인쇄중":6, "인쇄후":0}
```

인쇄용 스타일도 함께 넣었다. 사이드바·목차·버튼을 빼고,
화면에서 가로 스크롤이던 표와 코드는 넘침을 풀고,
표·코드가 페이지 경계에서 잘리지 않게 하고,
외부 링크는 주소를 각주처럼 붙였다.

## 해설의 숫자를 다시 계산해 봤다

교안이 이렇게 주장한다.

> `(a|b)*abb` 의 부분집합 구성 결과(5상태)를 최소화하면 4상태가 된다.

지금까지 이 숫자들은 "손으로 계산한 뒤 적어 둔 것"이었다.
Thompson 구성 → 부분집합 구성 → 분할 정제를 파이썬으로 따로 구현해 대조했다.

```
(a|b)*abb              Thompson NFA  14상태   부분집합 DFA  5상태   최소 DFA  4상태
(a|b)*                 Thompson NFA   8상태   부분집합 DFA  3상태   최소 DFA  1상태
(a|b)*a(a|b)(a|b)      Thompson NFA  22상태   부분집합 DFA  9상태   최소 DFA  8상태
```

| 교안의 주장 | 결과 |
|---|---|
| `(a\|b)*abb` 부분집합 5 → 최소 4 | ✅ |
| `(a\|b)*` Thompson 8 ($2n$ 상한과 정확히 일치) | ✅ |
| 뒤에서 3번째가 `a` 인 언어의 DFA 8상태 | ✅ |

도구로도 확인했다.

```
$ bison -v amb.y
amb.y: conflicts: 4 shift/reduce
State 9 conflicts: 2 shift/reduce
State 10 conflicts: 2 shift/reduce
```

20장 해설이 "상태 2개 × 연산자 2개 = 4개"라고 한 그대로다.

```
$ flex -v tokenizer.l
  273/2000 NFA states
  92/1000 DFA states
```

**전부 맞았다.** 내용 정확도는 이번에 문제가 없었다.

## 세 번째로 같은 실수를 했다

본문에서 이렇게 정의해 놓고

```md
**부트스트랩(bootstrapping)** 은 …
**셀프 호스팅(self-hosting)** 이라고 한다
**후위 순회(post-order)** 다
```

용어 사전에 넣지 않았다. 2차 감사에서 부트스트랩 절을 쓰면서,
3차에서 컴포넌트를 만들면서, 4차에서도 그랬다.

**세 번 반복했으면 사람이 고칠 문제가 아니다.**

```ts
const TERM_DEF = /\*\*([가-힣A-Za-z0-9 ·\-]{2,26})\s*\(([a-zA-Z][^)]{2,40})\)\*\*/g;
...
if (gloss.includes(ko)) continue;
issues.push({ rule: `사전에 없는 용어 — "${ko}" …` });
```

문장 속 번역일 뿐 용어가 아닌 것들(`수확(yield)`, `닫혀 있다(closed)`)은
`NOT_A_TERM` 에 적어 둔다. **"이건 용어가 아니다"라는 판단을 코드에 남기는 것**이
목적이라 allowlist 를 굳이 감추지 않았다.

이 규칙이 첫 실행에서 셋을 더 잡았다 — `복구 표현식`, `정의 절`, `소속 판정 문제`.

## 같은 것을 두 이름으로 부르고 있었다

`정의 절` 을 사전에 넣으려다 알았다.

```
정의부        7회
정의 절       3회      ← 같은 것
규칙부       18회
사용자 코드부  8회
```

`규칙부`·`사용자 코드부`와 짝이 맞게 `정의부`로 통일했다.

표기 후보 24쌍을 훑었는데 나머지는 전부 의도된 구분이었다.
`환원`은 "정지 문제로 환원된다"의 환원이고,
`구문 트리`는 AST와 followpos 구문 트리 둘 다 정당하다.

다만 이건 걸렸다.

```
스트링   100회
문자열    88회
```

층이 다른 말인데 그 약속이 어디에도 없었다. 2장에 넣었다.

| 말 | 무엇 |
|---|---|
| **스트링** | 이론에서 다루는 형식적 대상. $\Sigma^*$ 의 원소 |
| **문자열** | 프로그램 안의 실제 데이터. C의 `char *` |

`yytext` 가 담고 있는 것은 문자열이고, 그것이 나타내는 이론적 대상이 스트링이다.

## 표 행 하나가 표 밖으로 나가 있었다

빌드된 HTML을 훑다 발견했다.

```
<td>바이트코드 컴파일러 … HotSpot, V8</table>
<p>(JIT = Just-In-Time …)
| 전처리기 | 매크로 포함 소스 | 순수 소스 | cpp |</p>
```

1차 감사에서 JIT 설명을 표 중간에 끼워 넣으면서 **마지막 행이 고아가 됐다.**
파이프 문자가 본문에 그대로 찍히고 있었다. 같은 종류를 전수 검사했고 다른 곳은 없었다.

## 다섯 번의 감사가 남긴 것

| 회차 | 찾은 것 | 어떻게 |
|---|---|---|
| 1 | 내용 누락 (속성 문법, 생략된 계산) | 표준 교재 주제와 대조 |
| 2 | 조용한 렌더링 오류 (`\$`, `\|`) | 빌드 결과를 눈으로 |
| 3 | 자산 불균형, 끊어진 연결 | 장별로 세기 |
| 4 | admonition 제목 39곳 | **빌드된 HTML을 읽는 검사** |
| 5 | 인쇄, 표기 분열 | 안 해 본 사용 방식을 해 보기 |

매번 "글을 다시 읽어서" 찾은 것은 하나도 없다.
전부 **세거나, 대조하거나, 실제로 써 보거나** 해서 나왔다.

lint 규칙이 11개, 테스트가 97개, 그리고 빌드 결과 검사가 하나 있다.
전부 한 번씩 실제로 겪은 것들이다.

```bash
cd site && bun run check      # lint(11) + typecheck + 97 tests + build + lint:build
cd examples && make test      # 11개 예제 34케이스
```
