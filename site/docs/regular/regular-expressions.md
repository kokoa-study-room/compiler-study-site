# 4. 정규 표현

[3장](/docs/regular/regular-languages)에서 정규집합을 정의했다.
**정규 표현(regular expression)** 은 그 정규집합을 **적어 두기 위한 표기법**이다.

집합을 직접 쓰면 이렇다.

$$
\left(\{a\} \cup \{b\}\right)^* \{a\} \{b\} \{b\}
$$

정규 표현으로 쓰면 이렇다.

```
(a|b)*abb
```

같은 것을 가리키지만 후자가 압도적으로 짧다.
이 표기법이 있기에 lex 입력 파일 같은 것이 존재할 수 있다.

---

## 4.1 형식적 정의

:::info[정의 — 알파벳 $\Sigma$ 위의 정규 표현]

**기본**

| 정규 표현 | 나타내는 언어 $L(r)$ |
|---|---|
| $\emptyset$ | $\emptyset$ |
| $\varepsilon$ | $\{\varepsilon\}$ |
| $a$ (단, $a \in \Sigma$) | $\{a\}$ |

**귀납** — $r$ 과 $s$ 가 정규 표현이면

| 정규 표현 | 나타내는 언어 |
|---|---|
| $(r) \mid (s)$ | $L(r) \cup L(s)$ |
| $(r)(s)$ | $L(r)L(s)$ |
| $(r)^*$ | $(L(r))^*$ |
| $(r)$ | $L(r)$ |
:::

정의가 [정규집합의 정의](/docs/regular/regular-languages#31-정규집합의-정의)와
1:1로 대응한다는 점에 주목하자. 따라서 다음이 곧바로 따라온다.

> **정규 표현으로 쓸 수 있는 언어 = 정규언어**

### 연산자 우선순위

괄호를 매번 쓰면 읽을 수 없으므로 우선순위를 정한다.

| 우선순위 | 연산자 | 결합성 |
|---|---|---|
| 1 (가장 높음) | `*` (클로저) | — (후위 단항) |
| 2 | 접합 (나란히 쓰기) | 좌결합 |
| 3 (가장 낮음) | `\|` (합집합) | 좌결합 |

따라서

| 축약 표기 | 완전 괄호 표기 |
|---|---|
| `a\|b*c` | `a \| ((b*)c)` |
| `(a\|b)*abb` | `((a\|b)*)((a)(b)(b))` |
| `ab*` | `a(b*)` — `(ab)*` 가 아니다 |

:::caution[`ab*` 와 `(ab)*` 는 완전히 다르다]
- `ab*` = $\{a, ab, abb, abbb, \dots\}$ — `a` 하나 뒤에 `b` 여러 개
- `(ab)*` = $\{\varepsilon, ab, abab, ababab, \dots\}$ — `ab` 를 통째로 반복

`*`는 **바로 앞의 하나**에만 붙는다.
:::

### 예제

$\Sigma = \{a, b\}$ 일 때:

| 정규 표현 | 나타내는 언어 |
|---|---|
| `a\|b` | `a` 또는 `b` |
| `(a\|b)(a\|b)` | 길이 2인 모든 스트링 |
| `a*` | `a`가 0개 이상 |
| `(a\|b)*` | 모든 스트링 = $\Sigma^*$ |
| `a(a\|b)*` | `a`로 시작하는 모든 스트링 |
| `(a\|b)*abb` | `abb`로 끝나는 모든 스트링 |
| `b*(ab*ab*)*` | `a`가 짝수 개인 스트링 |
| `(a\|b)*a(a\|b)(a\|b)` | 뒤에서 3번째 글자가 `a` |

마지막 예를 곱씹어 보자. 이 언어를 인식하는 **DFA는 상태가 8개 필요**하다
(마지막 3글자를 전부 기억해야 하므로 $2^3$).
반면 NFA는 4개면 된다.
정규 표현이 짧다고 오토마타가 작은 것은 아니라는 좋은 예다.

## 4.2 정규 표현의 대수 법칙

두 정규 표현 $r$ 과 $s$ 가 같은 언어를 나타내면 $r = s$ 로 쓴다.

| 법칙 | 내용 |
|---|---|
| `\|` 교환 | $r \mid s = s \mid r$ |
| `\|` 결합 | $(r \mid s) \mid t = r \mid (s \mid t)$ |
| 접합 결합 | $(rs)t = r(st)$ |
| 분배 | $r(s \mid t) = rs \mid rt$, $(s \mid t)r = sr \mid tr$ |
| `\|` 항등원 | $r \mid \emptyset = r$ |
| 접합 항등원 | $\varepsilon r = r \varepsilon = r$ |
| 접합 영원 | $\emptyset r = r \emptyset = \emptyset$ |
| 멱등 | $r \mid r = r$ |
| 클로저 전개 | $r^* = \varepsilon \mid r r^*$ |
| 클로저 멱등 | $(r^*)^* = r^*$ |
| — | $\emptyset^* = \varepsilon$, $\varepsilon^* = \varepsilon$ |

:::caution[접합은 교환법칙이 성립하지 않는다]
$rs \neq sr$ 이 일반적이다. `ab` 와 `ba` 는 다른 언어다.
:::

:::note[$\emptyset$ 과 $\varepsilon$ 의 차이가 여기서 드러난다]
- $r \mid \emptyset = r$ — 아무것도 더하지 않음 (합집합의 항등원)
- $r \, \emptyset = \emptyset$ — 불가능한 것과 이으면 불가능 (접합의 영원)
- $r \, \varepsilon = r$ — 빈 것과 이으면 그대로 (접합의 항등원)

$\emptyset$ 을 "$\varepsilon$ 과 비슷한 것"으로 착각하면 이 세 줄이 전부 헷갈린다.
:::

### 법칙을 이용한 간소화

$$
(a \mid b)^* \;=\; (a^* b^*)^* \;=\; (a^* \mid b^*)^*
$$

셋 다 $\Sigma^*$ 를 나타낸다.
등식을 증명하려면 양방향 포함 관계 $L(r) \subseteq L(s)$ 와
$L(s) \subseteq L(r)$ 를 보이면 된다.

**주의.** 정규 표현의 등가성 판정은 **결정 가능하지만 비싸다**.
표준적인 방법은 양쪽을 DFA로 바꾸고 최소화한 뒤 동형인지 보는 것으로,
최악의 경우 지수 시간이 걸린다.

## 4.3 확장 표기

기본 세 연산만으로는 실용적이지 않아서, 축약 표기가 표준처럼 쓰인다.
**이들은 표현력을 늘리지 않는다** — 전부 기본 연산으로 풀어 쓸 수 있다.

| 표기 | 의미 | 기본 표기로 |
|---|---|---|
| `r+` | 1회 이상 반복 | `rr*` |
| `r?` | 0회 또는 1회 | `r\|ε` |
| `r{n}` | 정확히 n회 | `rr…r` (n번) |
| `r{n,m}` | n회 이상 m회 이하 | 전개 |
| `[abc]` | 문자 클래스 | `a\|b\|c` |
| `[a-z]` | 범위 | `a\|b\|…\|z` |
| `[^abc]` | 여집합 클래스 | $\Sigma$ 에서 `a,b,c` 제외 |
| `.` | 개행 제외 임의 문자 | `[^\n]` |

:::info[`r+` 와 `r*` 의 관계]
$$r^+ = rr^* = r^*r, \qquad r^* = r^+ \mid \varepsilon$$

즉 `+`는 "$\varepsilon$ 을 포함하지 않는 `*`"다.
`[0-9]+` 를 `[0-9]*` 로 잘못 쓰면 **빈 문자열도 숫자로 인정**되어
스캐너가 무한 루프에 빠진다. 흔한 실수다.
:::

### 정규 표현으로 표현할 수 없는 확장

현대 정규식 엔진(PCRE, Perl, Python `re`)의 기능 중
**형식 정규 표현이 아닌 것**들이 있다.

| 기능 | 예 | 정규인가? |
|---|---|---|
| 역참조 | `(a+)\1` | ❌ 정규가 아니다 |
| 전방 탐색 | `(?=...)` | ⭕ 정규이지만 표현이 커진다 |
| 재귀 패턴 | `(?R)` | ❌ 문맥 자유 이상 |

역참조 `(a+)\1` 은 $\{ww \mid w \in a^+\}$ 를 나타내는데,
이는 펌핑 보조정리로 정규가 아님을 보일 수 있다.

:::danger["정규식"과 "정규 표현"은 이제 다른 말이다]
실무의 "정규식(regex)"은 형식 언어 이론의 "정규 표현"보다 표현력이 크다.
그 대가로 **최악의 경우 지수 시간**이 걸릴 수 있다
(catastrophic backtracking, ReDoS).

lex/flex가 쓰는 것은 **순수한 정규 표현**뿐이다.
그래서 역참조가 없고, 대신 **입력 길이에 선형인 시간**을 보장한다.
DFA로 컴파일되기 때문이다. 어휘 분석기에는 이 보장이 훨씬 중요하다.

Go의 `regexp` 패키지와 Rust의 `regex` 크레이트도 같은 이유로
역참조를 지원하지 않고 선형 시간을 보장한다.
:::

## 4.4 정규 정의

복잡한 패턴을 한 줄에 다 쓰면 읽을 수 없다.
**정규 정의(regular definition)** 는 이름을 붙여 쌓아 올리는 방법이다.

:::info[정의]
$$
\begin{aligned}
d_1 &\to r_1 \\
d_2 &\to r_2 \\
&\vdots \\
d_n &\to r_n
\end{aligned}
$$

각 $d_i$ 는 새로운 이름이고, $r_i$ 는
$\Sigma \cup \{d_1, \dots, d_{i-1}\}$ 위의 정규 표현이다.

**핵심 제약: 자기 자신이나 뒤에 정의된 이름을 참조할 수 없다.**
즉 재귀가 금지된다. 재귀를 허용하면 정규언어를 벗어난다.
:::

**예제 — C 식별자와 수**

$$
\begin{aligned}
letter &\to \texttt{[A-Za-z\_]} \\
digit &\to \texttt{[0-9]} \\
id &\to letter\,(\,letter \mid digit\,)^* \\[0.4em]
digits &\to digit^+ \\
optFrac &\to (\,\texttt{.}\ digits\,)? \\
optExp &\to (\,\texttt{[eE]}\ (\texttt{+} \mid \texttt{-})?\ digits\,)? \\
number &\to digits\ optFrac\ optExp
\end{aligned}
$$

이 정규 정의는 `3`, `3.14`, `3.14e-2`, `6E7` 을 모두 인식한다.

이것을 lex 문법으로 그대로 옮기면:

```c
letter    [A-Za-z_]
digit     [0-9]
id        {letter}({letter}|{digit})*
digits    {digit}+
optFrac   (\.{digits})?
optExp    ([eE][+-]?{digits})?
number    {digits}{optFrac}{optExp}

%%
{id}       { return ID; }
{number}   { return NUM; }
```

lex의 **정의 절(definition section)** 이 정규 정의 그 자체임을 알 수 있다.
`{name}` 이 참조 문법이다.

:::caution[lex의 `{name}` 치환에는 괄호가 자동으로 붙지 않는다]
flex는 `{name}` 을 `(정의 내용)` 으로 감싸서 치환하지만,
POSIX lex나 일부 구현은 **그냥 텍스트로 치환**한다.
안전하게 쓰려면 정의 자체를 괄호로 감싸는 습관이 좋다.

```c
digit     [0-9]
digits    ({digit}+)
```
:::

## 4.5 lex/flex의 정규 표현 문법

flex에서 실제로 쓸 수 있는 표기를 정리한다.
[LEX 입력 파일 작성](/docs/lex/writing-lex-files) 장에서 다시 자세히 다루지만,
지금 표로 익혀 두면 이후가 편하다.

| 패턴 | 매치하는 것 |
|---|---|
| `x` | 문자 `x` |
| `.` | 개행을 제외한 임의의 한 문자 |
| `[xyz]` | `x`, `y`, `z` 중 하나 |
| `[a-z]` | `a`부터 `z`까지 |
| `[^a-z]` | `a`~`z`가 **아닌** 문자 |
| `r*` | `r` 0회 이상 |
| `r+` | `r` 1회 이상 |
| `r?` | `r` 0회 또는 1회 |
| `r{2,5}` | `r` 2~5회 |
| `{name}` | 정규 정의 참조 |
| `"[xyz]\"foo"` | 문자열 리터럴 `[xyz]"foo` (내부 메타문자 무효) |
| `\X` | 이스케이프 |
| `(r)` | 그룹 |
| `rs` | 접합 |
| `r\|s` | 선택 |
| `r/s` | **후행 문맥** — `s`가 뒤따를 때만 `r` 매치, 소비는 `r`만 |
| `^r` | 줄 처음의 `r` |
| `r$` | 줄 끝의 `r` (= `r/\n`) |
| `<<EOF>>` | 파일 끝 |

### 후행 문맥 `/` 의 유용함

FORTRAN의 고전적 예: `DO5I=1,25` 는 반복문이고
`DO5I=1.25` 는 `DO5I` 라는 변수에 대한 대입이다.
`,`를 볼 때까지 어느 쪽인지 알 수 없다.

```c
DO/({letter}|{digit})*=({letter}|{digit})*,   { return DO; }
```

`/` 뒤의 부분은 **매치 여부 판정에는 쓰이지만 소비되지 않는다**.
`yytext`에는 `DO`만 들어간다.

:::note[POSIX 문자 클래스]
flex는 로케일에 안전한 이름 붙은 클래스도 지원한다.

`[:alpha:]` `[:digit:]` `[:alnum:]` `[:space:]` `[:upper:]` `[:lower:]`
`[:punct:]` `[:xdigit:]`

대괄호 안에 넣어 쓴다: `[[:alpha:]_][[:alnum:]_]*`
:::

## 4.6 정규 표현으로 토큰 정의하기

실제 언어의 토큰 명세를 정규 표현으로 써 보자.

```c
/* 공백류 */
ws          [ \t\r\n]+

/* 식별자와 예약어 */
letter      [A-Za-z_]
digit       [0-9]
id          {letter}({letter}|{digit})*

/* 수 */
dec         [1-9]{digit}*|0
hex         0[xX][0-9a-fA-F]+
oct         0[0-7]+
float       {digit}+"."{digit}*([eE][+-]?{digit}+)?

/* 문자열: 이스케이프 허용, 개행 불가 */
string      \"([^"\\\n]|\\.)*\"

/* 주석 */
linecomment "//"[^\n]*
```

### 문자열 리터럴 패턴 뜯어보기

```
\"([^"\\\n]|\\.)*\"
```

| 조각 | 의미 |
|---|---|
| `\"` | 여는 따옴표 |
| `[^"\\\n]` | 따옴표·역슬래시·개행이 **아닌** 문자 |
| `\\.` | 역슬래시 + 아무 문자 (이스케이프 시퀀스) |
| `(...)*` | 위 둘 중 하나를 0회 이상 |
| `\"` | 닫는 따옴표 |

핵심은 `[^"\\\n]` 에서 역슬래시를 **제외**한 것이다.
제외하지 않으면 `"a\"b"` 에서 `\"` 를 문자열 끝으로 잘못 읽는다.

:::tip[이 패턴을 외우지 말고 이해할 것]
"끝 기호로 종료되지만 이스케이프는 예외" 라는 구조는
문자열·문자 상수·정규식 리터럴에 모두 똑같이 나타난다.

$$\texttt{Q} \; (\; [\char`\^\texttt{Q}\backslash] \mid \backslash. \;)^* \; \texttt{Q}$$

여기서 Q는 종료 기호다.
:::

### 블록 주석의 함정

C의 `/* ... */` 주석을 정규 표현 하나로 쓰려는 시도:

```c
/* ✗ 틀렸다: 첫 */ 가 아니라 마지막 */ 까지 먹는다 */
"/*".*"*/"
```

`.` 이 `*/` 도 포함하고 최장 일치가 적용되므로
`/*A*/ x /*B*/` 를 통째로 하나의 주석으로 먹어 버린다.

올바른 패턴은 "`*/` 가 나오기 전까지"를 정확히 표현해야 한다.

```c
"/*"([^*]|"*"+[^*/])*"*"+"/"
```

읽기 어렵다. 그래서 실무에서는 **시작 조건**을 쓴다.

```c
%x COMMENT
%%
"/*"              BEGIN(COMMENT);
<COMMENT>"*/"     BEGIN(INITIAL);
<COMMENT>.|\n     ;   /* 버린다 */
```

훨씬 읽기 쉽고, 중첩 주석으로 확장하기도 쉽다.
[LEX 입력 파일 작성](/docs/lex/writing-lex-files) 장에서 시작 조건을 자세히 다룬다.

## 요약

- **정규 표현**은 정규집합을 적는 표기법이고, 표현력은 정확히 정규언어와 같다.
- 우선순위는 `*` > 접합 > `|`. `ab*` 는 `a(b*)` 다.
- 대수 법칙 중 특히 $r^* = \varepsilon \mid rr^*$, $\emptyset r = \emptyset$,
  $\varepsilon r = r$ 를 구분해서 기억하자.
- `+`, `?`, `[...]`, `{n,m}` 은 **축약일 뿐** 표현력을 늘리지 않는다.
- **역참조는 정규가 아니다.** lex/flex는 역참조를 지원하지 않는 대신
  입력 길이에 **선형인 시간**을 보장한다.
- **정규 정의**는 이름을 붙여 쌓아 올리는 방법이며 재귀는 금지된다.
  lex의 정의 절이 바로 이것이다.
- 블록 주석처럼 "종료 기호까지" 패턴은 정규 표현 하나로 쓰기 어렵다.
  **시작 조건**을 쓰는 편이 낫다.

## 확인 문제

1. $\Sigma = \{a,b\}$ 위에서 다음 언어의 정규 표현을 써라.
   - (a) `a`가 정확히 2개인 스트링
   - (b) `aa`를 부분 스트링으로 포함하지 **않는** 스트링
   - (c) 길이가 4의 배수인 스트링
   - (d) `a`로 시작하고 `a`로 끝나는 길이 2 이상의 스트링
2. `(a|b)*a(a|b)(a|b)` 를 인식하는 DFA의 최소 상태 수는 몇 개인가? 왜 그런가?
3. 다음 등식이 참인지 판정하라.
   - (a) $(rs)^* r = r(sr)^*$
   - (b) $(r^* s^*)^* = (r \mid s)^*$
   - (c) $(r \mid s)^* = r^* \mid s^*$
4. 다음 정규 정의를 lex 문법으로 옮겨라.
   부호가 있을 수 있는 십진수: 선택적 `+`/`-`, 정수부, 선택적 소수부.
5. `"/*".*"*/"` 이 왜 틀렸는지 구체적인 입력을 들어 설명하고,
   올바른 패턴 `"/*"([^*]|"*"+[^*/])*"*"+"/"` 가 어떻게 동작하는지 분해하라.
6. `(a+)\1` 이 정규가 아님을 펌핑 보조정리로 증명하라.
