# 4. 정규 표현

[3장](/docs/regular/regular-languages)에서 정규집합을 정의했다.
**정규 표현(regular expression)** 은 그 정규집합을 **적어 두기 위한 표기법**이다.

집합을 직접 쓰면 이렇다.

$$
\left(\{a\} \cup \{b\}\right)^* \{a\} \{b\} \{b\}
$$

정규 표현으로 쓰면 이렇다.

```
(a|b)*abb
```

같은 것을 가리키지만 후자가 압도적으로 짧다.
이 표기법이 있기에 lex 입력 파일 같은 것이 존재할 수 있다.

---

## 4.1 형식적 정의

:::info[정의 — 알파벳 $\Sigma$ 위의 정규 표현]

**기본**

| 정규 표현 | 나타내는 언어 $L(r)$ |
|---|---|
| $\emptyset$ | $\emptyset$ |
| $\varepsilon$ | $\{\varepsilon\}$ |
| $a$ (단, $a \in \Sigma$) | $\{a\}$ |

**귀납** — $r$ 과 $s$ 가 정규 표현이면

| 정규 표현 | 나타내는 언어 |
|---|---|
| $(r) \mid (s)$ | $L(r) \cup L(s)$ |
| $(r)(s)$ | $L(r)L(s)$ |
| $(r)^*$ | $(L(r))^*$ |
| $(r)$ | $L(r)$ |
:::

정의가 [정규집합의 정의](/docs/regular/regular-languages#31-정규집합의-정의)와
1:1로 대응한다는 점에 주목하자. 따라서 다음이 곧바로 따라온다.

> **정규 표현으로 쓸 수 있는 언어 = 정규언어**

:::note[수식 읽는 법 — $L(r)$ 이 두 층을 이어 준다]
표의 왼쪽과 오른쪽은 **서로 다른 종류의 것**이다.

| | 왼쪽 열 | 오른쪽 열 |
|---|---|---|
| 무엇 | **정규 표현** — 우리가 종이에 쓰는 **글자** | **언어** — 스트링의 **집합** |
| 예 | `ab` (문자 두 개짜리 표기) | $\{ab\}$ (원소 하나짜리 집합) |
| 개수 | 유한한 기호 열 | 무한할 수 있다 |

$L(r)$ 은 그 사이를 잇는 함수다. **"표기를 넣으면 집합이 나온다."**

$$
L(\ \texttt{a}\mid\texttt{b}\ ) = \{a\} \cup \{b\} = \{a,\ b\}
$$

왼쪽의 `|` 는 **글자**이고 오른쪽의 $\cup$ 는 **연산**이다.
이 둘을 같은 것으로 보면 안 되지만, 대응이 1:1이라 실무에서는 섞어 쓴다.

**귀납 표를 한 줄씩 읽어 보자.**

| 쓴 것 | 소리 내어 읽으면 |
|---|---|
| $L((r) \mid (s)) = L(r) \cup L(s)$ | "$r$ 또는 $s$" 라고 쓴 것이 나타내는 언어는, 각각이 나타내는 언어의 **합집합** |
| $L((r)(s)) = L(r)L(s)$ | 나란히 쓴 것은, 각 언어에서 하나씩 뽑아 **이어 붙인** 것 전부 |
| $L((r)^*) = (L(r))^*$ | 별표를 붙인 것은, 그 언어에서 뽑아 잇기를 **0번 이상** 한 것 전부 |

**정의가 재귀적이라는 점**도 눈여겨보자.
$L$ 을 정의하는 데 $L$ 이 다시 나온다.
기본 세 줄이 재귀의 바닥이고, 표기가 유한하므로 언제나 바닥에 닿는다.
:::

### 연산자 우선순위

괄호를 매번 쓰면 읽을 수 없으므로 우선순위를 정한다.

| 우선순위 | 연산자 | 결합성 |
|---|---|---|
| 1 (가장 높음) | `*` (클로저) | — (후위 단항) |
| 2 | 접합 (나란히 쓰기) | 좌결합 |
| 3 (가장 낮음) | `\|` (합집합) | 좌결합 |

따라서

| 축약 표기 | 완전 괄호 표기 |
|---|---|
| `a\|b*c` | `a \| ((b*)c)` |
| `(a\|b)*abb` | `((a\|b)*)((a)(b)(b))` |
| `ab*` | `a(b*)` — `(ab)*` 가 아니다 |

:::caution[`ab*` 와 `(ab)*` 는 완전히 다르다]
- `ab*` = $\{a, ab, abb, abbb, \dots\}$ — `a` 하나 뒤에 `b` 여러 개
- `(ab)*` = $\{\varepsilon, ab, abab, ababab, \dots\}$ — `ab` 를 통째로 반복

`*`는 **바로 앞의 하나**에만 붙는다.
:::

### 예제

$\Sigma = \{a, b\}$ 일 때:

| 정규 표현 | 나타내는 언어 |
|---|---|
| `a\|b` | `a` 또는 `b` |
| `(a\|b)(a\|b)` | 길이 2인 모든 스트링 |
| `a*` | `a`가 0개 이상 |
| `(a\|b)*` | 모든 스트링 = $\Sigma^*$ |
| `a(a\|b)*` | `a`로 시작하는 모든 스트링 |
| `(a\|b)*abb` | `abb`로 끝나는 모든 스트링 |
| `b*(ab*ab*)*` | `a`가 짝수 개인 스트링 |
| `(a\|b)*a(a\|b)(a\|b)` | 뒤에서 3번째 글자가 `a` |

마지막 예를 곱씹어 보자. 이 언어를 인식하는 **DFA는 상태가 8개 필요**하다
(마지막 3글자를 전부 기억해야 하므로 $2^3$).
반면 NFA는 4개면 된다.
정규 표현이 짧다고 오토마타가 작은 것은 아니라는 좋은 예다.

## 4.2 정규 표현의 대수 법칙

두 정규 표현 $r$ 과 $s$ 가 같은 언어를 나타내면 $r = s$ 로 쓴다.

:::note[수식 읽는 법 — 이 등호는 "글자가 같다"가 아니다]
아래 표의 등호는 전부 **이런 뜻**이다.

$$
r = s \quad\text{는 사실}\quad L(r) = L(s) \quad\text{의 줄임말이다.}
$$

`a|b` 와 `b|a` 는 **글자로는 다르다**. 그런데 둘 다 $\{a, b\}$ 를 나타내므로 같다고 쓴다.

산수의 $2+3 = 3+2$ 와 같은 종류의 등호다.
왼쪽과 오른쪽은 **적는 방법**이 다를 뿐 **가리키는 것**이 같다.

그래서 법칙 하나를 증명하려면 **양쪽 집합이 서로를 포함함**을 보이면 된다.

$$
L(r) \subseteq L(s) \quad\text{이고}\quad L(s) \subseteq L(r) \quad\Longrightarrow\quad L(r) = L(s)
$$

**"$w \in L(r)$ 인 아무 $w$ 를 잡아 $w \in L(s)$ 임을 보이고, 반대로도 한다."**
집합의 상등을 보이는 표준 수법이고, 이 장의 증명은 전부 이 모양이다.
:::

| 법칙 | 내용 |
|---|---|
| `\|` 교환 | $r \mid s = s \mid r$ |
| `\|` 결합 | $(r \mid s) \mid t = r \mid (s \mid t)$ |
| 접합 결합 | $(rs)t = r(st)$ |
| 분배 | $r(s \mid t) = rs \mid rt$, $(s \mid t)r = sr \mid tr$ |
| `\|` 항등원 | $r \mid \emptyset = r$ |
| 접합 항등원 | $\varepsilon r = r \varepsilon = r$ |
| 접합 영원 | $\emptyset r = r \emptyset = \emptyset$ |
| 멱등 | $r \mid r = r$ |
| 클로저 전개 | $r^* = \varepsilon \mid r r^*$ |
| 클로저 멱등 | $(r^*)^* = r^*$ |
| — | $\emptyset^* = \varepsilon$, $\varepsilon^* = \varepsilon$ |

:::caution[접합은 교환법칙이 성립하지 않는다]
$rs \neq sr$ 이 일반적이다. `ab` 와 `ba` 는 다른 언어다.
:::

:::note[$\emptyset$ 과 $\varepsilon$ 의 차이가 여기서 드러난다]
- $r \mid \emptyset = r$ — 아무것도 더하지 않음 (합집합의 항등원)
- $r \, \emptyset = \emptyset$ — 불가능한 것과 이으면 불가능 (접합의 영원)
- $r \, \varepsilon = r$ — 빈 것과 이으면 그대로 (접합의 항등원)

$\emptyset$ 을 "$\varepsilon$ 과 비슷한 것"으로 착각하면 이 세 줄이 전부 헷갈린다.
:::

### 법칙을 이용한 간소화

$$
(a \mid b)^* \;=\; (a^* b^*)^* \;=\; (a^* \mid b^*)^*
$$

셋 다 $\Sigma^*$ 를 나타낸다.
등식을 증명하려면 양방향 포함 관계 $L(r) \subseteq L(s)$ 와
$L(s) \subseteq L(r)$ 를 보이면 된다.

**주의.** 정규 표현의 등가성 판정은 **결정 가능하지만 비싸다**.
표준적인 방법은 양쪽을 DFA로 바꾸고 최소화한 뒤 동형인지 보는 것으로,
최악의 경우 지수 시간이 걸린다.

## 4.3 확장 표기

기본 세 연산만으로는 실용적이지 않아서, 축약 표기가 표준처럼 쓰인다.
**이들은 표현력을 늘리지 않는다** — 전부 기본 연산으로 풀어 쓸 수 있다.

| 표기 | 의미 | 기본 표기로 |
|---|---|---|
| `r+` | 1회 이상 반복 | `rr*` |
| `r?` | 0회 또는 1회 | `r\|ε` |
| `r{n}` | 정확히 n회 | `rr…r` (n번) |
| `r{n,m}` | n회 이상 m회 이하 | 전개 |
| `[abc]` | 문자 클래스 | `a\|b\|c` |
| `[a-z]` | 범위 | `a\|b\|…\|z` |
| `[^abc]` | 여집합 클래스 | $\Sigma$ 에서 `a,b,c` 제외 |
| `.` | 개행 제외 임의 문자 | `[^\n]` |

:::info[`r+` 와 `r*` 의 관계]
$$r^+ = rr^* = r^*r, \qquad r^* = r^+ \mid \varepsilon$$

즉 `+`는 "$\varepsilon$ 을 포함하지 않는 `*`"다.
`[0-9]+` 를 `[0-9]*` 로 잘못 쓰면 **빈 문자열도 숫자로 인정**되어
스캐너가 무한 루프에 빠진다. 흔한 실수다.
:::

### 정규 표현으로 표현할 수 없는 확장

현대 정규식 엔진(PCRE, Perl, Python `re`)의 기능 중
**형식 정규 표현이 아닌 것**들이 있다.

| 기능 | 예 | 정규인가? |
|---|---|---|
| 역참조 | `([ab]+)\1` | ❌ 정규가 아니다 |
| 전방 탐색 | `(?=...)` | ⭕ 정규이지만 표현이 커진다 |
| 재귀 패턴 | `(?R)` | ❌ 문맥 자유 이상 |

역참조 `([ab]+)\1` 은 $\{ww \mid w \in \{a,b\}^+\}$ 를 나타내는데,
이는 펌핑 보조정리로 정규가 아님을 보일 수 있다
(사실 문맥 자유도 아니다 — [10장](/docs/parsing/context-free-grammar#cfg로도-안-되는-것) 참고).

:::caution[알파벳이 한 글자면 이야기가 다르다]
`(a+)\1` 처럼 알파벳이 `a` 하나뿐이면 $\{ww \mid w \in a^+\}$ 는
$\{a^{2n} \mid n \geq 1\}$, 즉 **길이가 짝수인 `a` 열**이다.
이것은 `(aa)+` 로 쓸 수 있는 **정규언어**다.

역참조가 표현력을 늘리려면 **알파벳에 기호가 둘 이상** 있어야 한다.
"같은 것이 두 번 반복"을 확인하려면 그 "같은 것"이 여러 가지일 수 있어야
기억할 정보가 무한해지기 때문이다.
:::

:::danger["정규식"과 "정규 표현"은 이제 다른 말이다]
실무의 "정규식(regex)"은 형식 언어 이론의 "정규 표현"보다 표현력이 크다.
그 대가로 **최악의 경우 지수 시간**이 걸릴 수 있다
(catastrophic backtracking, ReDoS).

lex/flex가 쓰는 것은 **순수한 정규 표현**뿐이다.
그래서 역참조가 없고, 대신 **입력 길이에 선형인 시간**을 보장한다.
DFA로 컴파일되기 때문이다. 어휘 분석기에는 이 보장이 훨씬 중요하다.

Go의 `regexp` 패키지와 Rust의 `regex` 크레이트도 같은 이유로
역참조를 지원하지 않고 선형 시간을 보장한다.
:::

## 4.4 정규 정의

복잡한 패턴을 한 줄에 다 쓰면 읽을 수 없다.
**정규 정의(regular definition)** 는 이름을 붙여 쌓아 올리는 방법이다.

:::info[정의]
$$
\begin{aligned}
d_1 &\to r_1 \\
d_2 &\to r_2 \\
&\vdots \\
d_n &\to r_n
\end{aligned}
$$

각 $d_i$ 는 새로운 이름이고, $r_i$ 는
$\Sigma \cup \{d_1, \dots, d_{i-1}\}$ 위의 정규 표현이다.

**핵심 제약: 자기 자신이나 뒤에 정의된 이름을 참조할 수 없다.**
즉 재귀가 금지된다. 재귀를 허용하면 정규언어를 벗어난다.
:::

:::note[수식 읽는 법 — 첨자 $i-1$ 이 재귀를 막는다]
조건에서 눈여겨볼 곳은 딱 하나, **첨자가 $i-1$ 까지**라는 것이다.

$$
r_i \ \text{는} \ \Sigma \cup \{d_1, \dots, d_{i-1}\} \ \text{위의 정규 표현}
$$

말로 읽으면 이렇다.

> $i$ 번째 정의의 오른쪽에는
> **원래 알파벳의 기호**와 **자기보다 앞에서 정의된 이름**만 쓸 수 있다.

$d_i$ 자신($i$)도, 뒤엣것($i+1$ 이후)도 안 된다.

**왜 이 제약이 필요한가.** 허용하면 이런 것을 쓸 수 있다.

$$
\textit{paren} \to \texttt{(}\ \textit{paren}\ \texttt{)} \mid \varepsilon
$$

읽어 보면 "괄호 안에 괄호"다. 이것은 [3.4절](/docs/regular/regular-languages#34-정규언어의-한계)에서
정규가 아님을 증명한 짝 맞추기 언어다.
**재귀를 한 줄 허용하는 순간 정규언어를 벗어난다.**

그래서 정규 정의는 언제나 **아래에서 위로 한 방향**으로만 쌓인다.

```
letter  →  [A-Za-z_]            ← Σ 의 기호만 씀
digit   →  [0-9]                ← Σ 의 기호만 씀
id      →  letter (letter|digit)*   ← 앞의 둘만 씀
```

**결국 전부 펼칠 수 있다.** 이름을 하나씩 본문으로 바꿔 넣으면
$\Sigma$ 의 기호만 남는 하나의 긴 정규 표현이 된다.
이름은 사람이 읽기 위한 것일 뿐, 표현력을 늘리지 않는다.
:::

:::caution[lex 의 `{name}` 도 같은 규칙을 따른다]
lex 정의부의 이름 참조가 정확히 이것이다.
자기 자신을 참조하면 flex 가 오류를 낸다 —
문법을 몰라서가 아니라 **DFA로 만들 수 없기 때문**이다.
재귀가 필요한 순간이 곧 [파서](/docs/parsing/context-free-grammar)로 넘어갈 때다.
:::

**예제 — C 식별자와 수**

$$
\begin{aligned}
letter &\to \texttt{[A-Za-z\_]} \\
digit &\to \texttt{[0-9]} \\
id &\to letter\,(\,letter \mid digit\,)^* \\[0.4em]
digits &\to digit^+ \\
optFrac &\to (\,\texttt{.}\ digits\,)? \\
optExp &\to (\,\texttt{[eE]}\ (\texttt{+} \mid \texttt{-})?\ digits\,)? \\
number &\to digits\ optFrac\ optExp
\end{aligned}
$$

이 정규 정의는 `3`, `3.14`, `3.14e-2`, `6E7` 을 모두 인식한다.

이것을 lex 문법으로 그대로 옮기면:

```c
letter    [A-Za-z_]
digit     [0-9]
id        {letter}({letter}|{digit})*
digits    {digit}+
optFrac   (\.{digits})?
optExp    ([eE][+-]?{digits})?
number    {digits}{optFrac}{optExp}

%%
{id}       { return ID; }
{number}   { return NUM; }
```

lex의 **정의부(definition section)** 가 정규 정의 그 자체임을 알 수 있다.
`{name}` 이 참조 문법이다.

:::caution[lex의 `{name}` 치환에는 괄호가 자동으로 붙지 않는다]
flex는 `{name}` 을 `(정의 내용)` 으로 감싸서 치환하지만,
POSIX lex나 일부 구현은 **그냥 텍스트로 치환**한다.
안전하게 쓰려면 정의 자체를 괄호로 감싸는 습관이 좋다.

```c
digit     [0-9]
digits    ({digit}+)
```
:::

## 4.5 lex/flex의 정규 표현 문법

flex에서 실제로 쓸 수 있는 표기를 정리한다.
[LEX 입력 파일 작성](/docs/lex/writing-lex-files) 장에서 다시 자세히 다루지만,
지금 표로 익혀 두면 이후가 편하다.

| 패턴 | 매치하는 것 |
|---|---|
| `x` | 문자 `x` |
| `.` | 개행을 제외한 임의의 한 문자 |
| `[xyz]` | `x`, `y`, `z` 중 하나 |
| `[a-z]` | `a`부터 `z`까지 |
| `[^a-z]` | `a`~`z`가 **아닌** 문자 |
| `r*` | `r` 0회 이상 |
| `r+` | `r` 1회 이상 |
| `r?` | `r` 0회 또는 1회 |
| `r{2,5}` | `r` 2~5회 |
| `{name}` | 정규 정의 참조 |
| `"[xyz]\"foo"` | 문자열 리터럴 `[xyz]"foo` (내부 메타문자 무효) |
| `\X` | 이스케이프 |
| `(r)` | 그룹 |
| `rs` | 접합 |
| `r\|s` | 선택 |
| `r/s` | **후행 문맥** — `s`가 뒤따를 때만 `r` 매치, 소비는 `r`만 |
| `^r` | 줄 처음의 `r` |
| `r$` | 줄 끝의 `r` (= `r/\n`) |
| `<<EOF>>` | 파일 끝 |

### 후행 문맥 `/` 의 유용함

FORTRAN의 고전적 예: `DO5I=1,25` 는 반복문이고
`DO5I=1.25` 는 `DO5I` 라는 변수에 대한 대입이다.
`,`를 볼 때까지 어느 쪽인지 알 수 없다.

```c
DO/({letter}|{digit})*=({letter}|{digit})*,   { return DO; }
```

`/` 뒤의 부분은 **매치 여부 판정에는 쓰이지만 소비되지 않는다**.
`yytext`에는 `DO`만 들어간다.

:::note[POSIX 문자 클래스]
flex는 로케일에 안전한 이름 붙은 클래스도 지원한다.

`[:alpha:]` `[:digit:]` `[:alnum:]` `[:space:]` `[:upper:]` `[:lower:]`
`[:punct:]` `[:xdigit:]`

대괄호 안에 넣어 쓴다: `[[:alpha:]_][[:alnum:]_]*`
:::

## 4.6 정규 표현으로 토큰 정의하기

실제 언어의 토큰 명세를 정규 표현으로 써 보자.

```c
/* 공백류 */
ws          [ \t\r\n]+

/* 식별자와 예약어 */
letter      [A-Za-z_]
digit       [0-9]
id          {letter}({letter}|{digit})*

/* 수 */
dec         [1-9]{digit}*|0
hex         0[xX][0-9a-fA-F]+
oct         0[0-7]+
float       {digit}+"."{digit}*([eE][+-]?{digit}+)?

/* 문자열: 이스케이프 허용, 개행 불가 */
string      \"([^"\\\n]|\\.)*\"

/* 주석 */
linecomment "//"[^\n]*
```

### 문자열 리터럴 패턴 뜯어보기

```
\"([^"\\\n]|\\.)*\"
```

| 조각 | 의미 |
|---|---|
| `\"` | 여는 따옴표 |
| `[^"\\\n]` | 따옴표·역슬래시·개행이 **아닌** 문자 |
| `\\.` | 역슬래시 + 아무 문자 (이스케이프 시퀀스) |
| `(...)*` | 위 둘 중 하나를 0회 이상 |
| `\"` | 닫는 따옴표 |

핵심은 `[^"\\\n]` 에서 역슬래시를 **제외**한 것이다.
제외하지 않으면 `"a\"b"` 에서 `\"` 를 문자열 끝으로 잘못 읽는다.

:::tip[이 패턴을 외우지 말고 이해할 것]
"끝 기호로 종료되지만 이스케이프는 예외" 라는 구조는
문자열·문자 상수·정규식 리터럴에 모두 똑같이 나타난다.

$$\texttt{Q} \; (\; [\char`\^\texttt{Q}\backslash] \mid \backslash. \;)^* \; \texttt{Q}$$

여기서 Q는 종료 기호다.
:::

### 블록 주석의 함정

C의 `/* ... */` 주석을 정규 표현 하나로 쓰려는 시도:

```c
/* ✗ 틀렸다: 첫 */ 가 아니라 마지막 */ 까지 먹는다 */
"/*".*"*/"
```

`.` 이 `*/` 도 포함하고 최장 일치가 적용되므로
`/*A*/ x /*B*/` 를 통째로 하나의 주석으로 먹어 버린다.

올바른 패턴은 "`*/` 가 나오기 전까지"를 정확히 표현해야 한다.

```c
"/*"([^*]|"*"+[^*/])*"*"+"/"
```

읽기 어렵다. 그래서 실무에서는 **시작 조건**을 쓴다.

```c
%x COMMENT
%%
"/*"              BEGIN(COMMENT);
<COMMENT>"*/"     BEGIN(INITIAL);
<COMMENT>.|\n     ;   /* 버린다 */
```

훨씬 읽기 쉽고, 중첩 주석으로 확장하기도 쉽다.
[LEX 입력 파일 작성](/docs/lex/writing-lex-files) 장에서 시작 조건을 자세히 다룬다.

## 요약

- **정규 표현**은 정규집합을 적는 표기법이고, 표현력은 정확히 정규언어와 같다.
- 우선순위는 `*` > 접합 > `|`. `ab*` 는 `a(b*)` 다.
- 대수 법칙 중 특히 $r^* = \varepsilon \mid rr^*$, $\emptyset r = \emptyset$,
  $\varepsilon r = r$ 를 구분해서 기억하자.
- `+`, `?`, `[...]`, `{n,m}` 은 **축약일 뿐** 표현력을 늘리지 않는다.
- **역참조는 정규가 아니다.** lex/flex는 역참조를 지원하지 않는 대신
  입력 길이에 **선형인 시간**을 보장한다.
- **정규 정의**는 이름을 붙여 쌓아 올리는 방법이며 재귀는 금지된다.
  lex의 정의부가 바로 이것이다.
- 블록 주석처럼 "종료 기호까지" 패턴은 정규 표현 하나로 쓰기 어렵다.
  **시작 조건**을 쓰는 편이 낫다.

## 확인 문제

1. $\Sigma = \{a,b\}$ 위에서 다음 언어의 정규 표현을 써라.
   - (a) `a`가 정확히 2개인 스트링
   - (b) `aa`를 부분 스트링으로 포함하지 **않는** 스트링
   - (c) 길이가 4의 배수인 스트링
   - (d) `a`로 시작하고 `a`로 끝나는 길이 2 이상의 스트링

<details>
<summary>풀이</summary>

**(a) `a`가 정확히 2개**

```
b*ab*ab*
```

`a` 사이사이와 양 끝에 `b` 가 얼마든지 올 수 있다.
`a` 를 정확히 두 번 적었으므로 개수가 고정된다.

**(b) `aa` 를 포함하지 않는 스트링**

```
(b|ab)*a?
```

발상: `a` 뒤에는 반드시 `b` 가 와야 한다(맨 끝은 예외).
따라서 문자열을 `b` 또는 `ab` 덩어리로 쪼갤 수 있고,
마지막에만 홀로 남은 `a` 가 올 수 있다.

| 입력 | 분해 | 판정 |
|---|---|---|
| `abab` | `ab`·`ab` | ✅ |
| `bba` | `b`·`b`·`a?` | ✅ |
| `aab` | 불가 — `aa` 를 만들 방법이 없다 | ❌ |

**(c) 길이가 4의 배수**

```
((a|b)(a|b)(a|b)(a|b))*
```

네 글자 묶음을 0회 이상 반복한다. $\varepsilon$ (길이 0)도 포함된다.

**(d) `a` 로 시작하고 `a` 로 끝나며 길이 2 이상**

```
a(a|b)*a
```

앞뒤의 `a` 가 서로 다른 글자이므로 길이가 자동으로 2 이상이다.

:::caution[`a(a|b)*a` 와 `a(a|b)a` 를 헷갈리지 말 것]
- `a(a|b)*a` — 가운데가 **0글자 이상**. `aa`, `aba`, `abba` 모두 ✅
- `a(a|b)a` — 가운데가 **정확히 1글자**. `aa` 는 ❌
:::

</details>

2. `(a|b)*a(a|b)(a|b)` 를 인식하는 DFA의 최소 상태 수는 몇 개인가? 왜 그런가?

<details>
<summary>풀이</summary>

**8개다.**

이 언어는 "**뒤에서 3번째 글자가 `a`**"인 스트링의 집합이다.

DFA는 결정적이므로 입력을 한 번만 훑으며 판정해야 한다.
그런데 "뒤에서 3번째"는 **입력이 끝나 봐야** 어디인지 알 수 있다.

따라서 DFA는 **항상 마지막 3글자를 기억**하고 있어야 한다.
입력이 끝나는 순간 그중 첫 번째가 `a` 였는지 보면 되기 때문이다.

마지막 3글자의 가능한 조합은

$$2 \times 2 \times 2 = 2^3 = 8 \text{ 가지}$$

각 조합이 하나의 상태다. `aaa`, `aab`, `aba`, `abb`, `baa`, `bab`, `bba`, `bbb`.
(입력이 3글자 미만인 경우는 `b` 로 채운 것으로 보면 된다.)

**두 상태가 구별 가능함을 보이면** 8개가 최소임이 증명된다.
서로 다른 두 조합 $u \neq v$ (둘 다 길이 3)에 대해,
첫 글자가 다르다면 꼬리 $\varepsilon$ 로 구별되고,
아니면 다른 위치가 첫 글자가 되도록 적당한 꼬리를 붙이면 구별된다.
Myhill–Nerode 정리에 의해 최소 상태 수는 8이다.

:::info[NFA는 4개면 된다]
NFA는 "**여기가 뒤에서 3번째라고 추측**"할 수 있다.

```
n0 --a,b--> n0 (자기 고리)
n0 --a--> n1 --a,b--> n2 --a,b--> n3 (종결)
```

상태 4개. 추측이 맞으면 종결에 도달하고, 틀리면 그 갈래가 죽는다.

**정규 표현이 짧다고 DFA가 작은 것은 아니다.**
일반화하면 "뒤에서 $n$번째"는 NFA $n+1$ 상태 vs DFA $2^n$ 상태다.
[6장의 상태 폭발](/docs/regular/representations#상태-폭발은-언제-일어나는가) 참고.
:::

</details>

3. 다음 등식이 참인지 판정하라.
   - (a) $(rs)^* r = r(sr)^*$
   - (b) $(r^* s^*)^* = (r \mid s)^*$
   - (c) $(r \mid s)^* = r^* \mid s^*$

<details>
<summary>풀이</summary>

**(a) 참이다.**

양변 모두 "$r$ 로 시작해 $sr$ 을 0회 이상 반복"을 나타낸다.

$$
\begin{aligned}
(rs)^*r &= \{\ r,\ rsr,\ rsrsr,\ \dots\ \} \\
r(sr)^* &= \{\ r,\ rsr,\ rsrsr,\ \dots\ \}
\end{aligned}
$$

$n$ 번 반복한 경우를 각각 쓰면 $(rs)^n r$ 과 $r(sr)^n$ 인데,
둘 다 $r\,s\,r\,s\,\cdots\,s\,r$ ($r$ 이 $n{+}1$ 개, $s$ 가 $n$ 개)로 같다.
괄호를 어디에 치느냐만 다르다.

**(b) 참이다.**

$\subseteq$ : $(r^*s^*)^*$ 의 원소는 $r$ 과 $s$ 를 이어 붙인 것이므로
$(r \mid s)^*$ 에 속한다.

$\supseteq$ : $(r\mid s)^*$ 의 원소 $x_1x_2\cdots x_k$ (각 $x_i$ 는 $r$ 또는 $s$) 는
$r^*s^*$ 를 $k$ 번 반복해 만들 수 있다 —
$x_i$ 가 $r$ 이면 $r^1s^0$, $s$ 면 $r^0s^1$ 로 고른다.

**(c) 거짓이다.**

`rs` 를 생각해 보자 ($r$ 과 $s$ 가 서로 다른 기호라고 하자).

- $(r \mid s)^*$ 에는 **있다** — $r$ 하나와 $s$ 하나를 이어 붙인 것
- $r^* \mid s^*$ 에는 **없다** — 이것은 "전부 $r$" 또는 "전부 $s$" 뿐이다

$$r^* \mid s^* = \{\varepsilon, r, rr, \dots\} \cup \{\varepsilon, s, ss, \dots\}$$

$r$ 과 $s$ 가 **섞인** 스트링이 하나도 없다.

:::tip[반례 하나면 충분하다]
등식이 **거짓**임을 보이려면 한쪽에만 있는 원소 **하나**를 제시하면 된다.
**참**임을 보이려면 양방향 포함을 모두 보여야 한다.
:::

</details>

4. 다음 정규 정의를 lex 문법으로 옮겨라.
   부호가 있을 수 있는 십진수: 선택적 `+`/`-`, 정수부, 선택적 소수부.

<details>
<summary>풀이</summary>

```c
digit     [0-9]
digits    ({digit}+)
sign      ([+-]?)
frac      ("."{digits})?
number    {sign}{digits}{frac}

%%
{number}   { printf("NUM(%s)\n", yytext); }
```

**인식하는 것:** `42`, `+42`, `-42`, `3.14`, `-0.5`, `+7.`? — 아니다.
`frac` 이 `"." {digits}` 이므로 소수점 뒤에 숫자가 **최소 하나** 필요하다.

| 입력 | 판정 |
|---|---|
| `42` | ✅ sign=ε, digits=`42`, frac=ε |
| `-3.14` | ✅ |
| `+0.5` | ✅ |
| `.5` | ❌ 정수부가 필수다 |
| `7.` | ❌ 소수점 뒤 숫자가 필요하다 |

**정의를 괄호로 감싼 이유**

```c
digits    ({digit}+)     ← 괄호를 쳤다
```

flex는 `{name}` 을 치환할 때 자동으로 괄호를 씌워 주지만,
**POSIX lex 등 일부 구현은 그냥 텍스트로 치환**한다.
그러면 `{digits}{frac}` 이 `digit+(.digit+)?` 로 풀려
`+` 의 결합이 의도와 달라질 수 있다.

정의 자체를 괄호로 감싸 두면 어느 구현에서도 안전하다.

:::caution[부호를 스캐너에 넣을지 파서에 넘길지]
실무에서는 부호를 **스캐너가 아니라 파서**가 처리하는 경우가 많다.

```
a-1
```

스캐너가 `-1` 을 하나의 수로 잘라 버리면 `a` 와 `-1` 두 토큰이 되어
**뺄셈이 사라진다**. 최장 일치가 그렇게 만든다.

그래서 대부분의 언어는 `-` 를 **단항 연산자 토큰**으로 두고
파서가 `- expr` 규칙으로 처리한다
([20장 `%prec UMINUS`](/docs/yacc/conflicts-and-precedence#prec--규칙의-우선순위를-직접-지정)).
:::

</details>

5. `"/*".*"*/"` 이 왜 틀렸는지 구체적인 입력을 들어 설명하고,
   올바른 패턴 `"/*"([^*]|"*"+[^*/])*"*"+"/"` 가 어떻게 동작하는지 분해하라.

<details>
<summary>풀이</summary>

**왜 틀렸는가**

```c
/*A*/ x /*B*/
```

`.` 은 개행을 제외한 **아무 문자**이므로 `*/` 도 포함한다.
그리고 lex는 **최장 일치**를 택한다.

| 후보 | 길이 |
|---|---|
| `/*A*/` | 5 |
| `/*A*/ x /*B*/` | 13 ← **최장 일치로 이것이 선택된다** |

결과: 두 주석 사이의 `x` 까지 통째로 주석으로 먹혀 사라진다.

**올바른 패턴 분해**

```
"/*"  (  [^*]  |  "*"+[^*/]  )*  "*"+  "/"
 ①       ②         ③          ④    ⑤   ⑥
```

| 조각 | 매치하는 것 | 왜 필요한가 |
|---|---|---|
| ① `"/*"` | 여는 `/*` | 시작 |
| ② `[^*]` | `*` 가 **아닌** 아무 문자 | 주석 본문의 평범한 글자 |
| ③ `"*"+[^*/]` | `*` 하나 이상 + `*` 도 `/` 도 아닌 문자 | 본문에 있는 `*` 를 안전하게 소비 |
| ④ `( … )*` | ②나 ③을 0회 이상 | 본문 반복 |
| ⑤ `"*"+` | `*` 하나 이상 | 닫는 부분의 시작 |
| ⑥ `"/"` | `/` | 종료 |

**핵심은 ③이다.** 본문에 `*` 가 나올 수 있는데, 그것이 `*/` 의 일부가 아님을
확인해야 한다. 그래서 `*` 뒤에 **`/` 가 아닌** 문자가 오는 경우만 본문으로 인정한다.

`*` 를 `+` 로 여러 개 받는 이유는 `***x` 같은 경우 때문이다.

**추적해 보자 — `/*a**b*/`**

```
/*      ①로 매치
a       ②로 매치 ([^*])
**b     ③으로 매치 ("*"+ 가 **, [^*/] 가 b)
*/      ⑤⑥으로 매치
```

`/*A*/ x /*B*/` 에서는 첫 `*/` 이후 더 진행할 수 없다.
`x` 를 ②로 받으려면 그 앞의 `/` 를 소비해야 하는데,
`*` 뒤의 `/` 는 ③에서 **명시적으로 제외**했기 때문이다. ✅

:::tip[그래서 실무는 시작 조건을 쓴다]
위 패턴은 **정확하지만 아무도 못 읽는다.**
[9장](/docs/lex/writing-lex-files#93-중첩-블록-주석)처럼 시작 조건을 쓰면

```c
%x COMMENT
"/*"              BEGIN(COMMENT);
<COMMENT>"*/"     BEGIN(INITIAL);
<COMMENT>.|\n     ;
```

읽기 쉽고, 중첩 주석으로 확장하기도 쉽다.
:::

</details>

6. `([ab]+)\1` 이 정규가 아님을 펌핑 보조정리로 증명하라.
   그리고 `(a+)\1` 은 왜 정규인지 설명하라.

<details>
<summary>풀이</summary>

**`([ab]+)\1` 이 나타내는 언어**

$$L = \{\ ww \mid w \in \{a,b\}^+\ \}$$

같은 문자열이 **두 번 반복**된 것. `abab`, `aa`, `abbabb` 등.

**증명 (귀류법).** $L$ 이 정규라 가정하고 펌핑 길이를 $p$ 라 하자.

$$z = a^p b\, a^p b$$

를 택한다. $w = a^pb$ 이므로 $z = ww \in L$ 이고 $\lvert z \rvert = 2p+2 \geq p$ 다.

$z = xyz'$ 로 쪼개면 조건 $\lvert xy \rvert \leq p$ 에 의해
$x$ 와 $y$ 는 **앞쪽 $a$ 들 안에만** 있다.

$$x = a^s,\quad y = a^t\ (t \geq 1),\quad z' = a^{p-s-t}b\,a^pb$$

$i = 2$ 로 펌프하면

$$xy^2z' = a^{p+t}\,b\,a^p\,b$$

이 스트링이 $L$ 에 있으려면 $uu$ 꼴이어야 한다.
길이가 $2p+t+2$ 이므로 $\lvert u \rvert = p + t/2 + 1$ 이고,
$u$ 는 앞 절반이다.

앞 절반에는 `b` 가 최대 한 개($t$ 가 짝수면 $a^{p+t/2}$ 로 `b` 가 없거나…),
뒤 절반과 `b` 의 위치가 다르다.
구체적으로 $t \geq 1$ 이므로 첫 `b` 의 위치가 $p+t+1$ 번째인데,
반으로 나눈 경계는 $p + t/2 + 1$ 번째다.
$t \geq 1$ 이면 $p+t+1 > p+t/2+1$ 이므로 **첫 `b` 가 뒤쪽 절반에 있다** —
즉 앞 절반은 전부 `a` 인데 뒤 절반에는 `b` 가 둘 있어 두 절반이 같을 수 없다.

따라서 $xy^2z' \notin L$. 모순. $\blacksquare$

**`(a+)\1` 은 왜 정규인가**

알파벳이 `a` 하나뿐이면

$$L' = \{\ ww \mid w \in a^+\ \} = \{\ a^{2n} \mid n \geq 1\ \}$$

즉 **길이가 짝수인(0 제외) `a` 열**이다. 정규 표현으로

```
(aa)+
```

**차이의 본질.** 역참조가 하는 일은 "앞에서 본 것과 **같은** 것인지 확인"이다.
- 알파벳이 하나면 "같은 것"이 **길이**뿐이고, 짝수인지만 보면 된다 — 유한한 정보
- 알파벳이 둘 이상이면 "같은 것"이 **문자열 자체**다.
  길이 $n$ 인 문자열이 $2^n$ 가지이므로 **무한한 정보**를 기억해야 한다

:::note[$\{ww\}$ 는 문맥 자유도 아니다]
스택으로도 안 된다. 스택은 LIFO이므로 앞부분을 **순서대로 다시** 읽을 수 없다.
[10장](/docs/parsing/context-free-grammar#cfg로도-안-되는-것)에서 다시 나온다.

반면 $\{ww^R\}$(회문)은 문맥 자유다 — 뒤집어 읽는 것이 바로 스택이 하는 일이다.
:::

</details>

7. `a|b*` 와 `(a|b)*` 가 나타내는 언어를 각각 $L(\cdot)$ 를 펼쳐 적고,
   두 언어가 다름을 원소 하나로 보여라.

<details>
<summary>풀이</summary>

**우선순위를 먼저 확인한다.** `*` 가 `|` 보다 세므로

| 축약 | 완전 괄호 |
|---|---|
| `a\|b*` | `a \| (b*)` |
| `(a\|b)*` | `((a\|b))*` |

**$L$ 을 펼친다.**

$$
L(\texttt{a} \mid \texttt{b}^*) = L(\texttt{a}) \cup L(\texttt{b}^*)
= \{a\} \cup \{\varepsilon, b, bb, bbb, \dots\}
$$

$$
= \{\,\varepsilon,\ a,\ b,\ bb,\ bbb,\ \dots\,\}
$$

$$
L((\texttt{a} \mid \texttt{b})^*) = \big(L(\texttt{a}) \cup L(\texttt{b})\big)^* = \{a, b\}^* = \Sigma^*
$$

**반례.** 스트링 `ab` 를 보자.

- $\texttt{ab} \in \Sigma^*$ 이므로 `(a|b)*` 에는 **있다**
- `a|b*` 는 "`a` 하나" **또는** "`b` 여럿"인데, `ab` 는 둘 다 아니다 → **없다**

$$
\texttt{ab} \in L((\texttt{a}\mid\texttt{b})^*), \qquad \texttt{ab} \notin L(\texttt{a} \mid \texttt{b}^*)
$$

원소 하나가 다르므로 두 집합은 다르다. $\blacksquare$

**핵심.** `a|b*` 에는 `a` 와 `b` 가 **섞인** 스트링이 하나도 없다.
합집합은 양쪽을 그냥 모을 뿐, 서로 이어 붙이지 않기 때문이다.
[4.2절의 반례](#법칙을-이용한-간소화)에서 $r^* \mid s^* \neq (r \mid s)^*$ 라고 한 것과 같은 이야기다.

</details>
